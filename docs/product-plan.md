# SuperHot 首期产品方案

记录日期：2026-10-19。首版本地系统已实现，实际能力与验证边界以 [README](../README.md) 为准。本文保留设计背景；Docker、会员与 AIGC 仍为后续范围。

## 定位和范围

SuperHot 长期定位为可扩展的商业助手；首期面向内部团队，围绕 TikTok 作者更新监控形成完整流程。每位用户自行提供并承担自己的 TikHub API Key 费用。首期约几百个监控对象。

用户已认可：链接识别后确认作者、独立检查间隔、首次历史基线、暂停恢复与手动检查、后台持续执行。

会员年费及支付仅记录为未来扩展，不创建虚假支付入口，也不提前构建钱包、充值、订阅账单。AIGC、其他平台、音频、ASR、自动归档和热榜发现后续另行定义。

## 页面和导航

| 页面 | 用户主要操作 |
| --- | --- |
| 官网 `/` | 了解监控能力、查看工作台示意、注册或登录 |
| 注册与登录 | 邮箱和密码注册/登录；密码重置渠道待实施时确定 |
| 概览 | 查看监控对象数、更新作品数、需处理的接口异常及最近更新 |
| 监控对象 | 添加链接、确认作者、设置间隔、搜索筛选、暂停恢复、手动检查 |
| 更新内容 | 按作者与日期筛选、查看视频或图片、复制文案、下载到本机 |
| 个人设置 | 管理自己的 TikHub Key、语言、展示时区和密码 |
| 系统管理（管理员） | 用户管理、SDK 当前/可用版本、更新说明、部署任务与运行日志 |

默认进入监控工作台。主操作始终清晰可见；添加监控使用一个抽屉或短表单，展示识别出的作者后再保存。普通用户不显示系统更新操作。

## 推荐视觉方向

采用原创 SuperHot 视觉，不依赖购买某个 MotionSites 模板才能继续开发。

- 官网：石墨黑背景、暖白文字、朱红/橙红品牌强调色；清晰的大标题、产品截图和适量线条动效。以实际监控工作台作为主要视觉，避免无关素材。
- 工作台：默认暖白或浅灰背景、深色文字、红色主操作；左侧固定导航，顶部简短标题和操作栏。大面积表格/内容卡片保持稳定。
- 动效：用于页面进入、抽屉打开、任务状态变化和操作反馈；支持减少动态效果偏好。
- 监控列表优先表格，更新内容提供适合视频和图集的卡片。错误状态明确区分 Key 失效、余额/额度不足、限流、暂时网络故障、目标不可访问。
- 桌面优先，同时支持手机上查看、暂停监控和下载。图标按钮提供文字提示，键盘和触摸操作均可用。
- 先覆盖中文、英文界面，并以 UTC 保存时间、按个人时区显示；浏览器可提供初始语言/时区建议。

MotionSites 用作排版和动效参考。其官方教程展示 React、TypeScript、Vite、Tailwind 和 Framer Motion 的组合。若以后采用具体收费模板或素材，再依据实际获得的模板内容和授权实现。

参考：[MotionSites 官方教程](https://motionsites.ai/lesson/build-animated-website-with-motionsites)、[官网示例库](https://motionsites.ai/?via=aigregator)。

## 用户与凭据

- 用户已确认监控列表与更新内容各自私有，默认只查看自己的监控；后端逐请求验证所有权，不创建团队共享空间。
- 管理员负责用户状态、系统运行与 SDK 维护，不默认获得查看用户明文 Key 的接口。
- API Key 在后端加密存储，界面仅回显掩码，普通日志不打印 Key 或授权请求头。
- 每用户配置一个首期活动 Key；更新 Key 后，新任务采用新凭据，在途任务按运行快照处理。
- 多人监控同一作者时，首期仍分别使用各自 Key 执行检查，防止跨用户借用额度或错误归属费用。
- 注册默认是否需要邀请/管理员审批是可配置的产品选择；上线默认值需在接入阶段明确，不影响当前架构。

## 素材下载

图片、视频以浏览器下载落到用户电脑。用户在远程电脑访问时，文件落到该远程电脑，不是服务器桌面目录。

优先使用可验证的媒体直链；直链无法直接下载时，由后端受控流式转发，响应附件文件名，不形成长期云端素材库。后端转发时仍占用网络带宽。下载源必须来自已解析的作品媒体字段并校验域名、重定向及目标地址，不提供任意 URL 下载接口。

图集提供逐图下载；是否提供一键 ZIP 由下一步交互原型确定。暂存如确有需要则设置短期清理，不作为长期归档。媒体直链可能过期，应在点击下载时刷新必要信息，并使用当前用户的 Key。

## 实施顺序与验收目标

1. 确认 API 数据：主页/作品链接识别同一作者，作品分页与去重，视频/图集字段，下载链路。
2. 搭建注册登录、加密凭据与用户隔离；普通用户不能操作其他人的资源。
3. 完成监控闭环，验证关闭网页后继续检查、进程重启后恢复、暂停生效、失败重试和 Key 失效提示。
4. 实现官网和简洁工作台，补齐中英文、时区、下载、基本运行记录。
5. 实现管理员 SDK 检测与受控升级；模拟候选版本不兼容，验证保持/恢复旧版本。
6. 提供 Windows/Linux 部署入口、数据库迁移、健康检查、备份恢复说明；在目标环境实际验证后才称为可一键部署。

## 部署约定

Windows 原生开发使用 Conda + Node + PostgreSQL。Linux 正式部署优先 Docker Compose，API 和 worker 使用同一套锁定的后端依赖，数据库单独持久化。前端构建产物不要求目标服务器安装 Node。

新设备部署需要 Docker/Compose、可用端口和必要配置。首次部署生成强随机应用密钥；迁移已有数据时转移原加密主密钥。数据库、密钥和备份独立于应用镜像保存。提供启动、停止、升级和备份恢复的明确命令，发布包不包含用户 API Key。

后续会员和 AIGC 通过独立业务模块接入已有账户、权限和任务设施，当前不构建通用插件市场或微服务平台。
