# 抖音监控接入

2026-10-20。当前使用 TikHub Python SDK 2.2.0，后端独立的 `DouyinProvider` 适配层接入现有监控、内容与下载流程。抖音和 TikTok 外观相似，但分页、响应字段及媒体域名分别处理。

## 添加监控

在「个人设置」保存本人的 TikHub Key，然后通过「添加监控」粘贴以下任一形式：

- `https://www.douyin.com/user/<sec_user_id>`，也支持数字用户 ID 和 `/share/user/...`。
- `https://www.douyin.com/video/<作品ID>` 或 `https://www.douyin.com/note/<作品ID>`。
- 带 `modal_id=<作品ID>` 的官方链接。
- `https://v.douyin.com/<短码>/`，可以直接粘贴包含它的整段分享消息。

系统展示作者资料，用户确认后创建私有监控，检查间隔为 1–168 小时。作品链接仅用于识别该作品的实际作者，后续检查对象是作者。首次检查保存首批历史内容，之后复用统一的增量去重、分页补查、暂停 / 恢复、手动检查和失败退避流程。

短链最多跟随 5 次跳转，只允许官方抖音地址，并校验 DNS 结果；不下载页面正文，也不携带 TikHub Key。无法展开时可改用完整主页或作品链接。

## SDK 调用

| 场景 | SDK 方法 | 主要参数 |
| --- | --- | --- |
| sec_user_id 主页 | `douyin_app_v3.handler_user_profile` | `sec_user_id` |
| 数字用户 ID 主页 | `douyin_web.fetch_user_profile_by_uid` | `uid` |
| 周期作品列表 | `douyin_app_v3.fetch_user_post_videos` | `sec_user_id`、`max_cursor`、`count=20`、`sort_type=0`、`channel=lite` |
| 作品链接识别与下载刷新 | `douyin_app_v3.fetch_one_video_v2` | `aweme_id` |

作品列表固定使用 `lite` 通道，原生响应要求 `aweme_list`、可识别的 `has_more` 与有效 `max_cursor`。接口结构异常会显示错误，不作为空列表处理。官方文档提示 `normal` 通道在部分账号可能缺少近期作品，因此当前选择 `lite`，不自动重复调用另一通道增加费用。每次周期检查的实际请求数还取决于补查页数。

作者身份使用返回的稳定 `uid`，采集使用 `sec_uid`。同一用户的跨平台账号不会因 ID 相同相互覆盖；各用户的 Key、监控、作品和下载权限继续隔离。`provider_data` 记录平台所需标识与通道，此次扩展无需增加数据库字段。

官方参考：[主页作品列表](https://docs.tikhub.io/186826223e0)、[单个作品详情 V2](https://docs.tikhub.io/186826220e0)、[SDK v2.2.0](https://github.com/TikHub/TikHub-API-Python-SDK/releases/tag/v2.2.0)。

## 视频、图文与下载

视频提取原生 `video` 内的可用播放 / 下载直链；图文提取 `images` 或 `image_post_info.images`，优先使用图片下载地址。图文中的背景音乐和合成播放字段不会生成视频下载按钮。

图片 ID 优先由素材标识生成，缺少标识时使用去除签名、缩放后缀和 CDN 主机后的路径生成，避免详情刷新、图片顺序变化时下载到另一张图片。刷新后无法找到原素材时返回明确错误，不按新的数组下标替换素材。

点击下载会使用当前用户的 Key 重新获取作品详情，再由后端向经过校验的平台媒体域名请求并流式转发；TikHub Key 不转发给媒体 CDN。文件由浏览器保存到当前电脑，服务端不长期归档。图片根据实际响应格式确定扩展名，单素材限制 256 MB。抖音播放地址可能再跳转到 CDN，下载器逐跳验证地址与文件类型。

文案来自接口返回的作品描述，可以复制；不包含语音识别或图片 OCR。私密、删除、受限或缺少有效素材直链的作品不能保证下载成功，会显示可理解的失败信息。

## 验证情况

- 全部 86 项后端测试、SDK 离线兼容检查、TypeScript / Vite 构建通过。
- 独立 QA 浏览器流程通过 TikTok / Twitter 回归、抖音分享消息识别确认、平台筛选、视频 / 双图下载及 320px 移动布局；下载请求使用稳定素材 ID。
- 新增 30 项后端检查覆盖链接、短链跳转边界、原生列表 / 详情、图文配乐区分、稳定素材 ID、分页去重、用户隔离和媒体转发。
- 使用用户提供的分享短链实测作者识别，取得首批 20 条视频，并取得首条视频详情；经 SuperHot 下载器收到 `video/mp4` 的前 65,536 字节后主动结束连接，没有保存完整视频。
- 实测响应用于制作脱敏回归样例：替换作者、作品 ID、正文、时间与媒体路径。图文样例为合成响应，真实图文接口与完整文件下载仍待实际样本验证。
- 自动测试使用模拟 TikHub HTTP 响应；浏览器验收使用独立数据库与模拟素材响应，不消耗 TikHub 额度，不往日常数据库写入示例监控。

此次实测仅发起作者资料、作品第一页及单条详情共 3 次 TikHub 请求，没有自动创建这个作者的长期监控。SDK 升级离线检查已加入抖音方法签名与响应样例，以便发现 SDK 层的不兼容变化；上游线上结构变化仍可能需要适配。
